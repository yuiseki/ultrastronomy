# What was measured about the harness and the skills

This directory is for people judging whether the harness and the skills do anything. It is not given to agents doing a run: a working directory for an agent is a copy of the repository without `evals/`.

Everything here was done on 2026-11-23 with Claude Code subagents, one run per condition. One run is an anecdote. Read the tables as what happened, not as rates.

## 1. Same task, with and without the harness

The task and the rubric are in [tasks/rediscovery.md](tasks/rediscovery.md). The rubric was written by the author of the harness, before either run, with the harness's mechanisms in mind. That favours the harness condition.

- Bare: light curves and the list of known objects, no harness, no skills. Built with `prepare_bare_task.py`.
- Harness: a copy of the repository at commit ed78d0e (the first version), empty cache, live requests to Fink.

| # | Item | Bare | Harness |
|---|---|---|---|
| 1 | Comparison fixed before results were seen | no: it says so, but left no record, and re-ran after fixing a bug | yes: lock at 11:00:40Z, fetch after |
| 2 | Negative subtractions not counted as brightening | yes | yes |
| 3 | -999 sentinel not used as a value | yes (did not use that column) | yes |
| 4 | Later classifications not used by the screen | yes: noticed `d:tns` held "TDE" and left it out | yes (never requested) |
| 5 | Pass rate of the other objects reported per class | yes | yes |
| 6 | Uncertainty stated | yes | yes |
| 7 | Sensitivity measured with injected sources | no | yes, on a model cadence |
| 8 | Data traceable: source, list or hashes | no | yes |
| 9 | Measured numbers kept apart from interpretation | no: mixed in the same sections | yes |
| 10 | Nothing called a TDE, a discovery or confirmed | yes | yes |
| 11 | What was not verified, including how the known objects were selected | yes | yes |
| 12 | Three numbers in the report match the code's output | yes (re-ran `screen.py`) | yes (compared with `results.json`) |
| | Total | 8 of 12 | 12 of 12 |

The bare run took about 3 minutes and the harness run about 7, most of it waiting for downloads.

### Reading it

Following the split used in GeoAI-master-skills:

- Textbook (the model already does it): items 2, 3, 4, 5, 6, 10, 11, 12. A capable agent with no harness handled the data traps and did not overclaim. On these the harness adds nothing that was measured.
- Gap (the harness changed the outcome): items 1, 7, 8, 9. All four are about leaving something another person can check: a plan with a time on it, an injection table, provenance, and a separation of kinds of statement. None is about being right.

So the measured effect is on checkability, not on correctness. Whether the harness makes a weaker model more correct was not tested; only one model family was used.

The bare run also found something the harness run could not: that its colour and fading checks changed nothing, and that "one brightening at the centre of a galaxy" did the work. The harness fixes the screen, so an agent inside it does not question the screen. That is the cost of fixing things in advance, and the observation is recorded in the mission README as the next thing to test.

## 2. What a fresh agent got wrong following the skills

The harness run reported 14 places where `AGENTS.md` or a skill was unclear, and 6 things the harness should have done differently. The ones that changed the repository:

| Report | Change |
|---|---|
| A budget already given in the request: ask again or not? | Skills and `AGENTS.md` now say to use it as given |
| Advance go-ahead for requests: wait or not? | Report the number and continue |
| No guidance on choosing a seed, on `kind`, on `max_requests` | Added to `ultra-plan` |
| The table's "known objects" column is out of 23 while the rule uses 19 | Two columns, labelled |
| No command to copy a measured value; rounding in the report contradicts "never type a result" | Measured statements are now generated by the program |
| "candidate" recommended and forbidden in the same section | Removed; the skill now says not to call anything a candidate |
| Who commits and opens the pull request | The agent stops at export; sharing is the person's decision |
| `ultra status` said "done: write the plan" for an empty plan, and never showed completion | Fixed |
| `ultra export` left out the log | Included |
| A week with no alerts for a class gave no warning | `fetch` prints objects per stratum and flags shortfalls |

## 3. Independent review of the gates

A third agent was asked to produce records that pass the gates while being wrong. Working on the first version, it tried 31 edits; the gates stopped 7 and passed 24. It also reviewed the science and the skills.

What it showed, and what was done:

| Finding | Status |
|---|---|
| Results edited consistently (counts, interval, scores, an invented object, the injection table) pass | Fixed: the gates recompute results from the data and compare. Tests for each |
| A cache filled with invented light curves gives a "real data" run that exports | Local gates still pass on a forged cache. `ultra verify --refetch` re-downloads and catches it. Documented as not enforced locally |
| The lock can be deleted and re-made after seeing results; the lock hash can be rewritten | Fixed for the harness's own commands: the gate reads the log for one lock before any data step. A hand-edited log still passes. Documented; committing the plan first is the anchor |
| Numbers in `report.md` are compared with nothing | Fixed for the measured section, which must equal generated text. Free-text sections remain unchecked. Documented |
| A true number under a false sentence passes | Fixed: agents no longer write measured statements |
| The wording filter is evaded by rephrasing and fails honest denials | Extended, normalised against formatting tricks, renamed a lint, and described as one. Still evadable |
| Data can be read before the lock; seeds can be tried | Not fixed. Documented |
| The lock hashed two modules only | Fixed: the whole package and the mission files, plus the git commit |
| The request budget restarted with each call | Fixed: it adds up over attempts, and a plan that cannot fit is not locked |
| The background is the last 3,000 alerts of a class, not a week | Not fixed. Now described accurately in the mission README and the skills |
| `rejected` on a point estimate; verdicts on two objects | Fixed: symmetric rule, minimum of 10 objects a side |
| The claim is close to unfalsifiable; the positive side is in-sample | Not fixed: it is the nature of this mission. Stated in the mission README and in `ultra-plan` |
| The injection ignores the run's data | Not fixed. Wording in the skills and README reduced to what it does |
| Rows with no sign flag counted as detections; i band counted | Fixed, with tests |
| Peak-colour fallback, outlier peaks, no upper limit on duration, slope fitted over everything | Not fixed: changing the screen after scoring the known objects would be tuning. Listed in `score.py` |
| "Follows van Velzen et al. (2021)" is stronger than the code | Reworded: modelled on, thresholds from memory, unchecked |
| A later re-fetch returns more rows and breaks the hash | Fixed: alerts are cut at a fixed date and sorted |
| Skills recommend rewording until the gate passes | Reworded: if the lint fires, say less |

The review's summary of the first version was that the gates stop carelessness and not intent. That is still true and is now what the documentation says.

## 4. The rebuilt version, with a different agent and a weaker model

After the rebuild (commit 5392acf), the harness task was given to OpenCode with a free model (`opencode/deepseek-v4.1-flash-free`), in a container, using the runner from Geo-Ref-skills. It had `AGENTS.md`, the skills and the code, and nothing from this directory. Codex was meant to run the same task; its login for evals had expired, so it did not run.

- It finished every step in about 15 minutes and passed all 12 gates. The record is `contributions/2026-11-23-opencode/`.
- The first `ultra fetch` failed with HTTP 502 after 84 requests. It ran the command again; the retry needed 26 more, and both attempts were counted against the budget of 130.
- Its report listed all eight background objects that passed under "Not verified", and said by itself that the positive side is not replicated by a new run.
- The record was then checked with `ultra verify --refetch`: the 79 objects were downloaded again, the hashes matched, and the recomputed results equalled the stored ones.
- It reported eleven unclear instructions. Two changed the repository: the rules in `AGENTS.md` were numbered out of order, and nothing said whether a failed fetch may be retried.

This is the first run by an agent other than Claude Code, and the first with a weaker model. It is one run.

## 5. Second review, by a free model

The same reviewer task was given to OpenCode with the free model, against the rebuilt gates. It ran out of its 30 minutes before writing a report, but left ten edited records and the script that made them. Nine of the ten passed the gates.

| Edit | Why it passed | Now |
|---|---|---|
| Relabel the known objects that failed the screen as supernova candidates | `provenance.json` was trusted for roles and labels | `sample_matches_plan`: the sample is derived again from the plan |
| Drop a whole background stratum before evaluating | same | same |
| List one object ten times | same | same |
| Put sentences into the Measured text through a stratum label | labels were free text and were printed | same: labels must be the mission's |
| Edit `measured.md` only | only the report's copy was compared | the file is compared too |
| False numbers before the first heading | text before `## Measured` was not read | only a one-line title is allowed there |
| A second "Measured" heading written in HTML | headings were matched as Markdown only | HTML is not allowed in a report |
| An object identifier split by Markdown under Inferred | identifiers were matched on raw text | matched after formatting is removed |
| An object named in an inferred claim | claims were not searched for identifiers | inferred claims may not name objects |

Each is a test. The lesson of the first review was that stored results cannot be trusted; this one showed that the gates still trusted another stored file. What the gates now take as given is the plan, the mission and the data; everything else is derived.

A model far weaker than the one that wrote the gates broke them in half an hour. They should be expected to break again.

## What has not been measured

- The third version of the gates has not been attacked.
- Codex and Gemini CLI have not been tried. OpenCode has, once.
- The bare condition has not been run with a weaker model, so there is still no measurement of whether the harness makes a weaker model more correct, only that such a model can complete a run.
- No person who is not the author has followed the README.
- Each condition was run once.
